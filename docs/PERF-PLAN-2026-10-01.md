Goal (owner's words, paraphrased): the macOS app should use less RAM and CPU while staying quick

Repo: `/Users/davidghermansteinberg/Desktop/Home/Projects/Code/BetterScreenshot` (the macOS app on
`main`; see `CLAUDE.md` for architecture). All paths below are relative to the repo root. Line

### Terms used below
- **Physical footprint:** the RAM macOS charges to the process (what Activity Monitor's "Memory"
  column shows). Measured with the built-in `footprint` / `vmmap` tools.
- **IOSurface:** GPU-shareable image memory, used by window backing stores, `CALayer` contents and
  ScreenCaptureKit frames. A lot of it while idle means images/windows are being kept alive.
- **MALLOC_SMALL:** ordinary heap allocations (objects, buffers).
- **Idle wake-ups:** how often the process is woken from sleep (timers etc.). These cost battery
  even when CPU % looks like zero.
- **BGRA / 420v:** pixel formats. BGRA = 4 bytes per pixel; `420YpCbCr8BiPlanarVideoRange` ("420v")
  = ~1.5 bytes per pixel, the format the H.264 video encoder uses natively.
- **Backing scale:** 2 on Retina screens (1 point = 2×2 pixels), 1 on non-Retina screens.
- **TestKit:** the project's local test harness (executable test runners under
  `Packages/*/Tests`), all run by `scripts/test.sh`.
- **Quick Access card:** the floating thumbnail shown bottom-right after a capture
  (`Packages/OverlayKit/.../QuickAccessOverlayController.swift`). **Pin:** a screenshot floated
  above all windows (`PinView.swift`). **Frozen screen:** the still image of the display grabbed when
  the capture hotkey is pressed, which the area selection is drawn over (`FrozenScreen`).

| Metric | Value |
|---|---|

| Physical footprint (peak since launch) | **316 MB** |
| IOSurface (idle) | 48 MB across 39 regions |
| MALLOC_SMALL (idle) | ~61 MB |
| CPU (idle) | ~0.1 % |
| Threads / ports | 16 / 507 |

Windows owned by the process while idle (both off-screen, both should not exist):
- `"Annotate"` 1470×833: the **last editor, closed but never deallocated** (see T1.1).
- untitled 440×100: the **onboarding window**, built at every launch and never shown (see T1.4).

The conclusion: idle CPU is already fine. **Memory is the main target**, plus per-capture
main-thread work (responsiveness) and memory while recording.

### How to measure (re-run before and after each change)

```sh
PID=$(pgrep -f "BetterScreenshot.app/Contents/MacOS/BetterScreenshot")
footprint $PID | head -12                                   # footprint + top categories
vmmap --summary $PID | grep -iE "IOSurface|MALLOC_SMALL|Physical footprint"
top -l 3 -s 5 -pid $PID -stats pid,cpu,mem,idlew,threads,ports | grep -E "^(PID|$PID)"
```

To list the app's windows (this is how the leaked editor was found), save this as `wins.swift`
somewhere outside the repo and run `swift wins.swift $PID`:

```swift
import CoreGraphics
let list = CGWindowListCopyWindowInfo([.optionAll], kCGNullWindowID) as! [[String: Any]]
for w in list where (w[kCGWindowOwnerPID as String] as? Int) == Int(CommandLine.arguments[1])! {
  print(w[kCGWindowNumber as String]!, w[kCGWindowLayer as String]!,
        w[kCGWindowIsOnscreen as String] ?? "-", w[kCGWindowBounds as String]!,
        w[kCGWindowName as String] ?? "")
}
```

A fair comparison: relaunch the app, do the same sequence each time (for example: 1 area capture →
Annotate → close editor → let the Quick Access card stay → open + close Settings and History), then
measure.

Size reference: one frozen frame of a 1470×833 pt Retina display is 2940×1666 BGRA ≈ **19.6 MB**.

## 3. Tier 1 — safe, small diffs, biggest RAM savings

### T1.1 Release the editor when it closes (~20–60 MB)
- **Where:** `App/Capture/CaptureCoordinator.swift:28` (`private var editorController:
  EditorWindowController?`) and `:49` (`editorController = controller`). Nothing ever sets it back
  to nil.
- **Effect:** after Done/⌘W the window, canvas, base `CGImage` (plus the full frozen frame, see
  T1.2), up to 50 undo + 50 redo snapshots
  (`Packages/EditorKit/Sources/EditorKit/EditorCanvasView.swift:40-41,71`), cached blur/pixelate
  patches (`RedactionAnnotations.swift:23,92`) and the three blur views
  (`EditorWindowController.swift:91,174,219`) all stay alive until the next Annotate.
- **Fix:** give `EditorWindowController` an `onClosed` callback fired from `windowWillClose` (same
  pattern as `TrimWindowController`, wired at `App/Recording/RecordingCoordinator.swift:~711`) and
  set `editorController = nil` in it. Optionally clear the undo/redo stacks in `windowWillClose`.
- Auditors checked for other strong references (TourCoordinator, TagOverlayController,
  WindowPlacer observers, canvas/inspector closures): all weak or removed. **Risk: none.**
- **Check:** after closing the editor, `wins.swift` no longer lists `"Annotate"`.

### T1.2 Crop copies its pixels instead of sharing the full frame (~20 MB per live capture)
- **Where:** `Packages/CaptureKit/Sources/CaptureKit/ImageCropper.swift:10`:
  `return image.cropping(to: clamped)`. Called from `FrozenScreen` (crop at
  `CaptureCoordinator.swift:~77`) and `CaptureKit/CaptureService.swift:37`.
- **Why it matters:** `CGImage.cropping(to:)` shares the parent's pixel data (Apple documents this).
  So even a 100×100 shot keeps the full ~20 MB frozen display alive as long as anything holds the
  crop: each Quick Access card (layer contents at
  `QuickAccessOverlayController.swift:130` + the `onCopy`/`onSave`/`onAnnotate`/`fileURLForDrag`
  closures at `CaptureCoordinator.swift:~216-221`), each pin (`PinView.image`), and the editor.
  This is probably a large part of the 48 MB idle IOSurface (not yet confirmed: measure with a card
  open before and after).
- **Fix:** in `ImageCropper.crop`, draw the cropped rect into a new `CGContext` the size of the crop,
  **keeping `image.colorSpace` and `bitmapInfo`** (so colours don't shift), and return `makeImage()`.
  Costs ~1–5 ms per capture. Add a TestKit test that the result has the right size/pixels and that
  colour space is preserved.
- **Risk:** low.

### T1.3 Quick Access card shows a downsampled preview (~15–19 MB per card)
- **Where:** `Packages/OverlayKit/Sources/OverlayKit/QuickAccessOverlayController.swift:130`
  (`imageLayer.contents = cg`, full-resolution image for a ~300 pt card).
- **Fix:** set the layer contents to a copy scaled to card size × backing scale (~600 px wide) and
  keep the full image only in the action closures (copy/save/annotate/drag).
- **Careful:** the contrast sampling (`BandLuminance`, `AspectFillMap`,
  `QuickAccessContrast.plan(for:)`) samples **at device resolution** on purpose (see `CLAUDE.md`,
  v2.9.0). Card size × backing scale *is* device resolution, so sample from the same downsampled
  image, but re-check the 4.5:1 guarantee still holds (the existing OverlayKit tests + a manual
  check on a white page).
- **Risk:** low.

### T1.4 Create windows only when needed; free Settings/History on close (~5–15 MB)
- Onboarding: `App/MenuBar/OnboardingController.swift:40-46` builds a 440×100 window with
  `defer: false`, `isReleasedWhenClosed = false`. `App/Lifecycle/AppDelegate.swift:108` creates the
  controller on every launch, even when permission is already granted. Fix: build the window
  lazily (on first `presentSetup`/`openSurface`), or `defer: true`.
- Settings (`App/Settings/SettingsWindowController.swift:31,50`) and History
  (`App/History/HistoryWindowController.swift:29,46`) keep their window, SwiftUI tree and blur
  backdrop forever after first open. Fix: on `willClose`, set `window = nil` (Settings also
  `bindingsWatch = nil`). Reopen costs ~50–150 ms; position is restored by `WindowPlacer`
  (`rememberAs:`).
- **Risk:** low.

### T1.5 Temp-file sweep timer only runs while there's something to sweep (idle wake-ups → ~0)
- **Where:** `App/Capture/TempFileService.swift:18-27`: a repeating 5 s `Timer` on the main run
  loop, no tolerance. Each tick lists all of `$TMPDIR` and stats files
  (`TempImageWriter.cleanExpired`, `Packages/CaptureKit/.../TempImageWriter.swift:~36-46`), even
  when no `BetterScreenshot-*` folder exists, and even when retention is ∞ (`maxAge` is nil). That's
  ~17,000 wake-ups/day.
- **Fix:** keep the launch sweep. Start the timer when `TempImageWriter` writes a file, stop it
  when a sweep finds no `BetterScreenshot-` folders left, don't schedule at all when retention is ∞,
  interval `max(5, retention / 10)`, `timer.tolerance = interval * 0.5`.
- **Must keep:** the sweep stays scoped to the `BetterScreenshot-` prefix (protects the in-progress
  GIF written to the temp root). See the "Temp-file retention" section in `CLAUDE.md`.
- **Risk:** none (files are deleted at about the same time).

### T1.6 Cache History thumbnails
- **Where:** `App/History/HistoryWindowController.swift:293` calls
  `App/History/HistoryService.swift:84` `thumbnail(for:)` → `NSImage(contentsOf:)` synchronously,
  inside the SwiftUI cell `body`. Hover/selection re-runs `body`, so the JPEG is re-read and
  re-decoded on the main thread every time.
- **Fix:** an `NSCache<NSUUID, NSImage>` in `HistoryService` with a `countLimit` (e.g. 120; the
  history cap is 100), emptied when the History window closes. Thumbnails are already 400 px JPEGs,
  so no change to how they're generated.
- **Risk:** none.

## 4. Tier 2 — responsiveness and lower per-capture peaks

### T2.1 Encode each screenshot to PNG once, off the main thread (~150–400 ms main-thread saved)
- **Where:** the same image is PNG-encoded up to 4× on main: history
  (`App/History/HistoryService.swift:37`), temp file for copy (`CaptureCoordinator.swift:~295`),
  save (`:~306`), drag-out (`:~221` → `DraggableImageView.swift:44`). Then
  `Packages/HistoryKit/.../HistoryStore.swift:49` decodes that PNG again to make the thumbnail.
- **Fix:** encode once in a background task, reuse the bytes for history file, temp file, saved file
  (when format is PNG) and pasteboard. Build the history thumbnail from the `CGImage` directly
  (draw into a ≤400 px context) instead of re-decoding. Show the card first; let the history write
  finish async.
- **Careful:** `historyID` becomes async. Restore Recently Closed needs the ID before a card can be
  dismissed: make dismissal await it or record the ID when ready.
- **Risk:** low–medium. This is the biggest diff in the plan; do it last in Tier 2.

### T2.2 Clipboard gets PNG, not TIFF
- **Where:** `CaptureCoordinator.swift:~287-299` and `HistoryService.swift:150-158` put an
  `NSImage` on the pasteboard, which AppKit serializes as TIFF (~4 bytes/pixel, ~20 MB full-screen).
  History copy also decodes the stored PNG just to re-wrap it.
- **Fix:** write `.png` data (bytes from T2.1) via `NSPasteboardItem`. For history, put the file's
  bytes on directly, no decode. Optionally add `.tiff` as a lazy data provider for old apps that only
  read TIFF.
- Also: `HistoryService.swift:47` uses `tiffRepresentation` for recording thumbnails. Pass a CGImage
  instead.

### T2.3 Pins scale on the GPU
- **Where:** `Packages/OverlayKit/Sources/OverlayKit/PinView.swift:52-55`: `draw(_:)` rescales the
  full image with high-quality interpolation on the CPU every scroll/resize frame.
- **Fix:** `layer.contents = cgImage`, `contentsGravity = .resizeAspect`, remove `draw(_:)`.

### T2.4 Stop mic/camera without blocking the UI (50–300 ms hitches)
- `Packages/RecordingKit/Sources/RecordingKit/MicCapturer.swift:46`:
  `sessionQueue.sync { session.stopRunning() }`, called on main from
  `App/Recording/RecordStripController.swift` `refreshMeter`/`stopMeter` (~403, ~427).
- `Packages/RecordingKit/Sources/RecordingKit/CameraBubbleController.swift:67`:
  `session?.stopRunning()` on main.
- **Fix:** `async` on the session queue (the serial queue already guarantees start/stop order;
  `CameraBubbleController.swift:83` already does it this way).

### T2.5 Lighter redraws in the editor and the video editor (CPU while drawing/playing)
- Editor: `Packages/EditorKit/Sources/EditorKit/EditorCanvasView.swift:~421` sets
  `needsDisplay = true` per drag event, and `draw(_:)` (~231-313) ignores the dirty rect and redraws
  the full-resolution base image (~240) plus every annotation. Fix: put the base image in a
  background layer (`layer.contents`, keeping nearest-neighbour zoom via `magnificationFilter`) so
  `draw` paints annotations only, **or** invalidate just old ∪ new bounding box + handle margin.
- Redaction: `RedactionAnnotations.swift:42-56` re-renders blur/pixelate via CoreImage every drag
  tick. `Redactor.swift:5` `CIContext(options: nil)` → add `.cacheIntermediates: false`; optionally
  draw the stale patch shifted during a drag and re-render on mouse-up / every ~30 ms.
- Video editor: `Packages/RecordingKit/.../TrimWindowController.swift:177` periodic observer at
  1/30 s → `CutTimelineView.swift:18` `needsDisplay = true` → `drawFilmstrip` (~127-150) walks
  every tile of the segment. Fix: invalidate only the old/new playhead strips; start the tile loop at
  `dirtyRect.minX`.
- Low priority: `TextAnnotation.swift:40-46` rebuilds the attributed string + bounding rect on every
  draw; cache keyed on text + style + wrap width if text-heavy edits feel slow.

### T2.x Small, optional
- Window capture queries `SCShareableContent` twice (`CaptureCoordinator.swift:~353` and
  `CaptureService.swift:21`), 10–50 ms. Pass it through.
- `BandLuminance.swift:24-29` computes luminance and sorts twice. Once is enough (<2 ms).
- `GIFExporter.swift:42-46`: no `autoreleasepool` around per-frame adds. **Unverified**: measure GIF
  export peak first, then wrap each iteration if it grows with length.

## 5. Tier 3 — changes behaviour; owner must decide first

### T3.1 Recording pixel format (~60–120 MB less while recording)
- `Packages/RecordingKit/Sources/RecordingKit/ScreenRecorder.swift:115-116`:
  `sc.pixelFormat = kCVPixelFormatType_32BGRA`, `sc.queueDepth = 6`, at full backing resolution.
  4 bytes/px, ~21 MB per 2880×1800 frame, up to 6 in flight, plus a conversion before H.264.
- **Proposal:** `kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange` (~1.5 bytes/px, the encoder's
  native format) and `queueDepth = 4`. Nothing in the recorder reads pixels, **but** check: colours
  in the MP4 (side-by-side with a BGRA recording), GIF export path, paused `heldFrame`, camera
  bubble/click overlays as they appear in the video.
- Likely a big part of the 316 MB peak.

### T3.2 Non-Retina (1x) displays are captured at 2x
- `Packages/CaptureKit/Sources/CaptureKit/CaptureService.swift:47-48` (window) and `:85-86`
  (display) hard-code `* 2` (comment: "capture at @2x; refined later"). On a 1x external monitor
  every capture and frozen frame has 4× the pixels (1080p → ~33 MB).
- **Proposal:** use the display's real backing scale. **Behaviour change:** screenshots from 1x
  screens become their true pixel size (smaller files, no upscaling). Possibly related to the
  outstanding "stretched-resolution black bar" item in `CLAUDE.md`, which needs the owner's hardware.
  Don't change without them.

## 6. Checked and fine (no action, so nobody re-audits it)

Recording overlays (strip, controls pill, camera bubble, click/keystroke, countdown, window picker)
are created on show and torn down on hide, with event monitors removed. HUD toast panel freed after
1.5 s. Frozen-screen selection windows are dropped in `finish()`/`cancel()` (only the shared-crop
issue in T1.2 keeps the frame). Quick Access stack is capped and dismiss frees the card. Trim
window is released via `onClosed`; its time observer is removed. Recording timer 1 Hz only while
recording; tour timers (10 Hz follow, 2 Hz watchdog) only while a tour shows; `TourTagRecordingGate`
4 Hz only while recording. Vision loads only for Capture Text. No `SCShareableContent` at launch.
One shared `CIContext` (`Redactor.swift:5`), not per call. Undo snapshots share the base `CGImage`
(no image copies). History thumbnails are 400 px JPEGs made with
`CGImageSourceCreateThumbnailAtIndex`; full images are only decoded for annotate/pin/copy.
